# Enhanced Evaluation Features

## 🎯 New Capabilities Added

### 1. **AI-Generated Code Detection** ✨

The evaluator now automatically detects if code appears to be AI-generated:

**Detection Methods:**
- **Explicit markers**: Comments like "Generated by AI", "ChatGPT", "Copilot generated"
- **Comment density**: AI tends to over-comment (>30% comment lines triggers alert)
- **Boilerplate patterns**: Detects phrases like "template", "placeholder", "example code"

**Scoring Impact:**
- If AI code detected: Deducts 10-30 points from Code Quality score
- Shows AI likelihood percentage in evaluation
- Lists specific indicators found

**Example Output:**
```
⚠️ AI-GENERATED CODE DETECTED (Likelihood: 65%)
Indicators: chatgpt, Excessive comments, Contains "boilerplate"
```

---

### 2. **Smarter Individual Scoring** 🧠

Individual scores are now based on **quality over quantity**:

**Old Method (Removed):**
- ❌ 50% based on commit count
- ❌ 50% based on lines of code
- ❌ No consideration of commit importance

**New Method (Implemented):**
- ✅ **60% Quality**: Importance of files changed, complexity of code
- ✅ **40% Quantity**: Commits and lines, but weighted
- ✅ **Quality Score** calculated per contributor (0-100)

**Quality Score Factors:**
1. **Important file changes (40%)**: Changes to core code vs config files
2. **Non-trivial commits (30%)**: Meaningful commits vs tiny tweaks
3. **Code volume balance (30%)**: Sweet spot of 20-200 lines/commit

**Important vs Trivial Files:**
- **Important**: `.py`, `.js`, `.jsx`, `.ts`, `.tsx`, `.java`, etc. (core logic)
- **Trivial**: `README.md`, `.json`, `.css`, `package-lock.json` (docs/config)

---

### 3. **Code Originality Checks** 🔍

**Detects Suspicious Patterns:**
- Massive single commits (>1000 lines) - possible copy-paste
- Very small commits (<5 lines) repeatedly - possible busy work
- One person doing >80% of work - unfair distribution
- No commits to important files - only docs/config changes

**Work Distribution Analysis:**
- Flags if one team member did <5% or >80% of meaningful work
- Considers quality, not just quantity
- Penalizes severely imbalanced teams

## 🎓 Evaluation Criteria Updates

### Updated Scoring Guidelines:

**Individual Contributions (15 points):**
- Base **60% on quality** (complexity, importance, critical features)
- Base **40% on quantity** (commits, lines of code)
- Penalize if work distribution is unfair (one person >80% or <5%)
- Reward meaningful contributions over trivial commits

**Code Quality (20 points):**
- **Deduct 10-30 points** if AI-generated code detected without disclosure
- Consider code originality and authenticity
- Check for proper attribution if using external code

## 🔄 How It Works

### Evaluation Flow:

```
1. Clone Repository
2. Analyze Contributors
   ├─ Count commits
   ├─ Analyze changed files (important vs trivial)
   ├─ Detect commit patterns
   └─ Calculate quality score
3. Extract Code Files
4. Detect AI-Generated Code
   ├─ Scan for AI markers
   ├─ Check comment density
   └─ Identify boilerplate patterns
5. Send to Gemini AI with:
   ├─ Code samples
   ├─ Contributor quality metrics
   ├─ AI detection results
   └─ Enhanced scoring guidelines
6. Receive Evaluation:
   ├─ Total score (0-100)
   ├─ Category breakdown
   ├─ Individual scores (quality-weighted)
   ├─ AI detection report
   └─ Detailed feedback
7. Write to Google Sheet
```

## ⚠️ Important Notes

### AI Detection Limitations:
- Not 100% accurate (no detection method is perfect)
- May have false positives/negatives
- Should be used as a **flag for review**, not absolute proof

### Quality Score Considerations:
- Favors balanced commits (20-200 lines/commit)
- Penalizes both tiny commits and massive dumps
- Prioritizes changes to core code files
- May not perfectly capture all contribution types

### Recommendations:
1. Review flagged cases manually
2. Use AI detection as one factor, not the only factor
3. Consider context (maybe AI was allowed/encouraged)
4. Talk to students about any concerns
